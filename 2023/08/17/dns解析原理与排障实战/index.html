DNS 解析原理与排障实战

“网站打不开”的排查里，DNS 是最容易被忽略、又最常出问题的一层——IP 能访问、域名不能，十有八九就是它。这篇把 DNS 的完整解析流程和排障方法讲透。

一、DNS 是什么

DNS（域名系统）把域名翻译成 IP，好比电话簿：记名字不记号码。端口：一般走 UDP 53，数据量大或区域传输时走 TCP 53。

常用记录类型：

记录 作用 示例
A 域名 → IPv4 www.example.com → 1.1.1.1
AAAA 域名 → IPv6 —
CNAME 别名（CDN 加速常用） www 指向 cdn.example.com

常用公共 DNS：阿里 223.5.5.5、腾讯 119.29.29.29、114.114.114.114、谷歌 8.8.8.8。

四、三个真实故障案例

案例 1：网站突然打不开，IP 能访问、域名不能

排查链路：nslookup 域名 → 超时/无记录 → 查 /etc/resolv.conf → 发现 nameserver 写的是内网 DNS → 换 223.5.5.5 立即可解析。

根因：公司内网 DNS 故障/上游被污染。解决：切换 DNS 或同时配置多个 nameserver（nameserver 223.5.5.5 + nameserver 114.114.114.114）。

案例 2：dig +trace 发现权威服务器返回异常 IP（域名被劫持）

现象：解析结果指向一个不明 IP，访问弹广告。

处理：联系域名服务商核查解析记录；检查是否有 CNAME 被篡改；确认域名管理后台没有被盗号（查登录记录、改强密码）。

案例 3：CDN 切换后部分地区访问慢

现象：CDN 配置已切换，但部分用户还访问旧节点。

根因：LDNS 缓存了旧 IP，TTL 未到。处理：等 TTL 过期，或通知运营商刷新缓存。

生产规范：改解析前先看当前 TTL，提前把 TTL 调小（如 300 秒）再改记录，改完再恢复 TTL——避免切换后长时间缓存旧地址。

五、DNS 排障心法

遇到”域名不通”，按这个顺序走：本机 dig 看解析结果 → hosts 有没有污染 → resolv.conf 对不对 → 换公共 DNS 交叉验证 → dig +trace 看链路 → 联系域名服务商。其中”换公共 DNS 交叉验证”能快速区分是”本地 DNS 问题”还是”权威解析问题”，是效率最高的一步。
